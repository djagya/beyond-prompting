# Приёмы сетапа, которые стоит перенять

**Практические заметки из кастомизированного Hermes-сетапа Данила; не обязательный шаблон развёртывания.**

Это карта переносимых решений, а не копия приватной конфигурации. Контроли нужно адаптировать к своим аккаунтам, инструментам и рискам.

Начни с [агентского входа](agent-start.ru.md): карта возможностей и запасные маршруты. Достаточно одного controller; приватные профили, workers, memory services и deployment paths не являются предпосылками. Конкретные контракты исполнения — в [рабочих циклах](operating-loops.ru.md).

## 1. Изучать опыт, затем механизм

Используй [извлечение уроков за неделю](weekly-learning-extraction.ru.md): сначала ревью, затем проверка текущих владельцев, внедрение — после ограниченного мандата. Неудачный результат может означать конфликт инструкций или отсутствие нужной возможности, а не недостающее правило.

## 2. Один владелец конечного результата

Controller сохраняет интеграцию, внешние полномочия и итоговую проверку. Workers получают ограниченные задания по своим реальным возможностям. [Один агент по умолчанию](../readings/single-agent-by-default.ru.md) помогает решить, окупается ли делегирование. Уведомление или handoff ещё не является доставкой результата.

## 3. Разделять текущее состояние, процедуры и историю

Действующее решение имеет одного подходящего владельца. Процедуры живут в reusable skills; состояние проекта — в проектных артефактах; приватные свидетельства остаются приватными. Исторический пересказ не должен конкурировать с последующей пользовательской коррекцией. Source и deployed state проверяются отдельно.

## 4. Проверять заказанную работу

Докажи полезный исход, а не только успешный вызов инструмента: документ должен читаться, визуальная карта — оставаться визуальной, доступ — подтверждаться безопасным запросом, temporal-ответ — датированным свидетельством. Непройденные проверки называй явно.

## 5. Явные внешние границы

Возможность не равна полномочию. Неавторизованный браузер не доказывает отсутствие API-маршрута; настроенный credential — работающий доступ. Сохраняй origin binding, native secret transport, подтверждения и безопасное поведение при неоднозначном результате. См. [hardening guide](hermes-hardening.md).

## 6. Использовать существующего lifecycle owner

Сначала штатные jobs, supervision и recovery, затем — дополнительный watcher, если его необходимость доказана. Controller должен иметь ясное условие остановки: результат получен, настоящий блокер, ожидаемая внешняя работа или исчерпан ограниченный бюджет. Не превращай ожидание workers и CI в busy polling.

## Форк Hermes

[Форк Данила](https://github.com/djagya/hermes-agent) — поверхность кастомизации и интеграции, используемая вместе с этими методами. [Upstream Hermes](https://github.com/NousResearch/hermes-agent) остаётся исходным проектом.

Состав веток и включение изменений в upstream меняются. Заметка не утверждает, что каждое изменение форка отсутствует upstream, требуется для этих методов или подходит чужому развёртыванию. Перед использованием проверь выбранную ветку, diff с актуальным upstream, tests и release notes; выбери известную ревизию. Default branch форка не обязательно совпадает со сборкой, которую сейчас использует владелец.
